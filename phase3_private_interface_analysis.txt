12. Key trigger assessment
--------------------------
A. Subscription change
[DEVICE CONFIRMED] subId 11 -> -1 -> 11 occurred in physical path.
[SOURCE CONFIRMED] ImsResolver consumes slot -> subId and carrier config state when binding carrier IMS services.
[INFERRED] This is a necessary trigger for the observed remove/add/rebind chain, because ImsResolver sees a real slot identity transition rather than merely toggling IMS.

B. CarrierConfig CLEAR_CONFIG / no-SIM / ESSENTIAL_LOADED / LOADED
[DEVICE CONFIRMED] This exact sequence occurred in physical path.
[SOURCE CONFIRMED] CarrierConfigLoader has per-phone update and clear logic and Xiaomi ABSENT/LOADED hooks.
[INFERRED] CarrierConfig clearing/loading is likely required to force stale VOXI/WFC policy state out and make IMS/IWLAN re-evaluate with fresh slot/subscription state.

C. ImsResolver remove/rebind
[DEVICE CONFIRMED] MMTEL/RCS remove/add/rebind occurred.
[SOURCE CONFIRMED] ImsResolver binds services based on subId and carrier config readiness.
[INFERRED] This is likely a key consequence of subscription/config lifecycle rather than a standalone first step.

D. Phone/ImsPhone recreation
[DEVICE CONFIRMED] Physical path had enough lifecycle churn to refresh IMS state.
[SOURCE CONFIRMED] Current static artifacts expose ImsPhone state reset methods, but no safe direct Phone/ImsPhone recreate API was found.
[INFERRED] A direct ImsPhone reset is less faithful than rebuilding subscription/config and allowing framework observers to rebuild IMS features.

E. UICC recreation
[DEVICE CONFIRMED] Physical SIM removal/insertion implies UICC absent/present.
[SOURCE CONFIRMED] QTI setUiccApplicationsEnabled path can deactivate/activate UICC card via QtiUiccCardProvisioner.
[INFERRED] This is the closest internal analogue to physical SIM absent/present, but it is also high risk because it affects UICC provisioning/card state.

F. IWLAN/ePDG reinitialization
[DEVICE CONFIRMED] IWLAN is the final healthy access network.
[SOURCE CONFIRMED] No precise per-slot IWLAN reset API was recovered.
[INFERRED] IWLAN/ePDG recovery is probably downstream of IMS registration after subscription/config rebuild.


13. Does disable-physical-subscription produce 11 -> -1?
--------------------------------------------------------
[SOURCE CONFIRMED] The command is wired to a physical-subscription handler, validates physical SIM vs eSIM, and uses SubscriptionManager.

[SOURCE CONFIRMED] The ROM contains SubscriptionController/QtiSubscriptionController methods capable of disabling subscription/UICC applications for subId 11, deactivating the QTI UICC card by slot, refreshing active subscription cache, and notifying subscription info changes.

[INFERRED] This makes subId invalidation or at least active-subscription removal plausible. It is the best static candidate for producing the ImsResolver-observed slot 1 subId 11 -> -1 transition.

[DEVICE CONFIRMED] Not yet confirmed for this command. The 11 -> -1 transition is confirmed only for the physical remove/no-SIM boot path.

-------------------------------------------------------

[INFERRED] This makes subId restoration plausible, especially if disable-physical-subscription first causes the framework to remove/deactivate the active sub.

[DEVICE CONFIRMED] Not yet confirmed for this command. The -1 -> 11 transition is confirmed only for physical SIM insertion after no-SIM state.


15. Current best minimal private-interface hypothesis
-----------------------------------------------------
[INFERRED] The closest theoretical no-reboot/no-physical-removal state rebuild is:

1. Make slot 1/subId 11 temporarily lose active physical subscription/UICC application availability.
2. Let SubscriptionController/SubscriptionInfoUpdater notify active subscription change.
3. Let CarrierConfigLoader see ABSENT/no-SIM and clear phoneId 1 config.
4. Let ImsResolver observe slot 1 subId invalid / -1 and remove MMTEL/RCS features.
5. Re-enable slot 1/subId 11 physical subscription/UICC applications.
6. Let UICC/subscription records reload for phoneId 1.

=== PRIVATE INTERFACE FINDINGS ===

A. Closest to physical "remove SIM"
[CANDIDATE ONLY] cmd phone disable-physical-subscription 11, internally associated with SubscriptionManager / SubscriptionController / QtiSubscriptionController physical subscription and UICC application disabling. QTI source path reaches deactivateUiccCard(slotId), refreshCachedActiveSubscriptionInfoList(), and notifySubscriptionInfoChanged(). Risk Level 4.

B. Closest to physical "insert SIM"
[CANDIDATE ONLY] cmd phone enable-physical-subscription 11, symmetric path likely reaching QtiSubscriptionController.setUiccApplicationsEnabled(true,11) and activateUiccCard(slotId). Risk Level 4.

C. Closest to CarrierConfig CLEAR/LOAD
[CANDIDATE ONLY] CarrierConfigLoader.updateConfigForPhoneId(1,"ABSENT") for absent/no-SIM side and updateConfigForPhoneId(1,"ESSENTIAL_LOADED"/"LOADED") for reload side. Xiaomi MiCarrierConfigLoaderImpl also routes ABSENT to onIccAbsent(phoneId) and LOADED to onIccLoaded(phoneId). Risk Level 2, but direct invocation is a framework write operation and not tested.

D. Closest to ImsResolver remove/rebind
[INFERRED] The best remove/rebind trigger is not resetIms(1) alone. It is the subscription + CarrierConfig lifecycle that forces ImsResolver to re-evaluate slot 1 with subId -1 and then 11. Direct resetIms(1) only reaches ImsResolver.disableIms(1) in the recovered ROM path and is incomplete. Risk Level 2/3.

E. Most likely to affect only VOXI slot 1/subId 11
[CANDIDATE ONLY] CarrierConfigLoader phoneId 1 update is the most scoped but incomplete. IMS reset/enable/disable for slot 1 is scoped but incomplete. physical-subscription enable/disable is subId 11 scoped at API entry, but because it touches UICC provisioning and subscription notifications it is Level 4.

F. Can disable-physical-subscription produce 11 -> -1?
[INFERRED] Plausible and currently the strongest candidate, because it reaches physical subscription/UICC deactivation and subscription notification code. [DEVICE CONFIRMED] Not yet confirmed for this command; confirmed only for physical remove/no-SIM path.

G. Can enable-physical-subscription produce -1 -> 11?
[INFERRED] Plausible as the symmetric activation path. [DEVICE CONFIRMED] Not yet confirmed for this command; confirmed only for physical insertion path.

H. Current most worthwhile next-stage test candidates
[CANDIDATE ONLY] Do not execute without explicit user approval and a rollback/observation plan.

1. Highest-fidelity, highest-risk: controlled slot 1 test of disable-physical-subscription 11 followed by enable-physical-subscription 11, while capturing only targeted read-only before/after evidence: subscription list, CarrierConfig logs, ImsResolver state, IMS registration, IWLAN.
2. Lower-risk, less faithful: targeted CarrierConfig phoneId 1 absent/load experiment, if a safe privileged invocation route is found. This may refresh config but probably will not reproduce subId 11 -> -1.
3. IMS-only fallback: reset/disable/enable IMS for slot 1. Static evidence says this is least faithful to the Golden recovery mechanism and should not be expected to solve stale subscription/CarrierConfig state by itself.
