AOSP behavior:
  - [AOSP INFERRED] CarrierConfigLoader has EVENT_CLEAR_CONFIG and EVENT_DO_FETCH_DEFAULT_FOR_NO_SIM_CONFIG. clearConfigForPhone(phoneId, fetchNoSimConfig) clears cached carrier/default config state and, when requested, starts the no-SIM default config path.
  - [AOSP INFERRED] updateConfigForPhoneId(phoneId, simState) is permission-gated by MODIFY_PHONE_STATE and is the framework entry that causes config reload for SIM state changes.

9. Truly important trigger points
=================================

A. CarrierConfig CLEAR_CONFIG:
  - Status: [DEVICE CONFIRMED] and [AOSP INFERRED].
  - Role: likely necessary for faithful reproduction of the physical remove/insert path.
  - Evidence: exact chain CLEAR_CONFIG -> no-SIM config -> ESSENTIAL_LOADED -> LOADED is observed for phoneId 1. AOSP confirms this clears per-phone config state.
  - Why it matters: IMS service choice, WFC booleans, IWLAN policy, and MMTEL availability are carrier-config-dependent.
  - Caveat: CLEAR_CONFIG alone is probably insufficient if subId remains 11 and ImsResolver does not remove/rebind features.

B. Subscription 11 -> no subId / -1 -> 11:
  - Status: [DEVICE CONFIRMED].
  - Role: likely necessary for the closest no-reboot equivalent.
  - Evidence: ImsResolver explicitly logs slot 1 subId 11 -> -1 on removal and -1 -> 11 after load.
  - Why it matters: ImsResolver and feature connectors key state by slot/subId; a normal airplane toggle does not normally invalidate the subscription identity.

C. ImsResolver remove/rebind:
  - Status: [DEVICE CONFIRMED] and [AOSP INFERRED].
  - Role: likely necessary for rebuilding the framework IMS feature graph.
  - Evidence: removeConnection/addConnection around both subId transitions, then MMTEL READY.
  - Caveat: not equivalent to restarting org.codeaurora.ims; the observed path is more precise and per-slot/feature-scoped.

D. Phone / ImsPhone recreation:
  - Status: boot creation [DEVICE CONFIRMED]; hotplug recreation [NOT CONFIRMED].
  - Role: possible companion, not proven necessary.
  - Evidence: setSubId/connectionReady events are confirmed; full Phone object recreation during hotplug is not.
  - Conclusion: do not make this a required minimal step unless later logs prove Phone/ImsPhone object teardown.

E. UICC recreation:
  - Status: first insertion creation [DEVICE CONFIRMED]; physical absence/presence behavior [AOSP INFERRED] and indirectly confirmed during 12:07/12:08.
  - Role: likely upstream trigger for subscription and CarrierConfig lifecycle.
  - Evidence: UiccCard/UiccProfile creation at insertion; AOSP disposes card on absent and creates on present.
  - Caveat: simulating UICC absent/loaded is high-risk and likely touches SIM/UICC/radio.

F. IWLAN/ePDG reinitialization:
  - Status: Android network outcome [DEVICE CONFIRMED]; vendor daemon internal reset [NOT CONFIRMED].
  - Role: necessary final outcome, but not necessarily the earliest trigger.
  - Evidence: final MOBILE[IWLAN] IMS network and PS/WLAN HOME.
  - Caveat: resetting IWLAN directly may be broader and riskier than triggering the upstream subscription/config/IMS lifecycle.

14. Risk classification
=======================

Level 0: Pure reads
  - service list
  - dumpsys phone / carrier_config / telephony.registry / connectivity / package
  - cmd phone ims get-ims-service -s 1
  - cmd phone cc get-value -s 1
  - read-only file listing under /system, /system_ext, /product, /vendor, /odm

Level 1: Theoretically only slot 1 / phoneId 1
  - A privileged CarrierConfig updateConfigForPhoneId(1, LOADED) style reload.
  - A read-write Binder transaction that only reloads phoneId 1 CarrierConfig, if precisely identified.

Level 2: May rebuild slot 1 IMS
  - ImsResolver.resetIms(1), if accessible.
  - cmd phone ims enable/disable -s 1.
  - A direct slot 1 MMTEL feature reset through telephony_ims, if identified.

Level 3: May affect the whole IMS service
  - cmd phone ims set-ims-service / clear-ims-service-override.
  - org.codeaurora.ims service unbind/rebind.
  - vendor.qti.iwlan service rebind.
  - com.qti.phone ExtTelephony methods if method scope is unclear.

Level 4: May affect dual-SIM or radio
  - cmd phone disable-physical-subscription 11 / enable-physical-subscription 11.
  - Synthetic UICC ABSENT/LOADED.
  - Radio/modem service binding changes.
  - Restarting qcrild or vendor IMS/IWLAN daemons.

Level 5: Equivalent to reboot / high risk
  - reboot.
  - stop/start framework or radio services.
  - kill/kill -9 com.android.phone, qcrild, org.codeaurora.ims, ims* daemons.
  - modem restart.


15. Minimal state rebuild reasoning
===================================

What must be preserved from the physical path:
  - [DEVICE CONFIRMED] CarrierConfig must pass through phoneId 1 clear/no-SIM and then ESSENTIAL_LOADED/LOADED for VOXI.
  - [DEVICE CONFIRMED] ImsResolver must observe slot 1 subId 11 -> -1 -> 11.
  - [DEVICE CONFIRMED] slot 1 MMTEL feature connection must be removed/re-added and end READY for subId 11.
  - [DEVICE CONFIRMED] IWLAN must end in PS/WLAN HOME and MOBILE[IWLAN] IMS/MMTEL connected for subId 11.

What may be companion state rather than necessary:
  - [NOT CONFIRMED AS NECESSARY] Full Phone object recreation.
  - [NOT CONFIRMED AS NECESSARY] Restarting org.codeaurora.ims or Qualcomm IMS daemons.
  - [NOT CONFIRMED AS NECESSARY] Direct IWLAN service restart.
  - [NOT CONFIRMED AS NECESSARY] RCS readiness, because WFC calling depends on MMTEL.

Why airplane mode ON/OFF is not equivalent:
  - It can toggle radio power and registration, but the observed successful path specifically includes subscription invalidation, CarrierConfig CLEAR_CONFIG/no-SIM reload, ImsResolver feature remove/re-add, and then IWLAN/IMS recovery.
  - If the broken state is a stale carrier-config/subscription/IMS feature graph, airplane mode may leave the stale graph intact.


=== MINIMAL REBUILD CANDIDATE ===

This is a candidate sequence only. It was not executed.

1. Make slot 1 / subId 11 framework-visible as absent or no-subscription.
   - Desired observed equivalent: ImsResolver slot 1 subId 11 -> -1.
   - Closest known candidate: disable physical subscription 11, or a lower-level subscription/UICC absent simulation.
   - Risk: Level 4.

2. Trigger phoneId 1 CarrierConfig CLEAR_CONFIG and no-SIM default config load.
   - Desired observed equivalent: EVENT_CLEAR_CONFIG -> EVENT_DO_FETCH_DEFAULT_FOR_NO_SIM_CONFIG -> EVENT_FETCH_DEFAULT_FOR_NO_SIM_CONFIG_DONE.
   - Closest known candidate: privileged CarrierConfig updateConfigForPhoneId(1, ABSENT), if it can be invoked precisely.
   - Risk: Level 1 to Level 2 if direct; Level 4 if caused via physical-subscription disable.

3. Let ImsResolver remove slot 1 MMTEL/RCS under subId=-1.
   - Desired observed equivalent: removeConnection/addConnection subId=-1, MMTEL UNAVAILABLE.
   - Best path: indirect via steps 1 and 2, not direct IMS disable.
   - Risk: Level 2 to Level 3.

4. Restore slot 1 / subId 11.
   - Desired observed equivalent: Active subscription info list contains subId 11, setDefaultDataSubId 11, MMTEL/RCS setSubId 11.
   - Closest known candidate: enable physical subscription 11, or internal subscription reload.
   - Risk: Level 4.

5. Trigger phoneId 1 CarrierConfig ESSENTIAL_LOADED and LOADED reload.
   - Desired observed equivalent: ESSENTIAL_LOADED -> EVENT_DO_FETCH_DEFAULT -> LOADED -> EVENT_DO_FETCH_DEFAULT -> EVENT_SUBSCRIPTION_INFO_UPDATED.
   - Closest known candidate: privileged CarrierConfig updateConfigForPhoneId(1, ESSENTIAL_LOADED/LOADED), if subId 11 is restored.
   - Risk: Level 1 to Level 2 if direct; Level 4 if caused via subscription/UICC operations.

6. Let ImsResolver re-add/rebind slot 1 MMTEL/RCS for subId 11.
   - Desired observed equivalent: ImsResolver slot 1 subId -1 -> 11, removeConnection/addConnection subId=11, MMTEL READY.
   - Best path: indirect via subId/config reload.
   - Risk: Level 2 to Level 3.

7. Let IWLAN/ePDG recover naturally from the rebuilt subscription/config/IMS graph.
   - Desired observed equivalent: PS/WLAN HOME, mIsIwlanPreferred=true, MOBILE[IWLAN] IMS/MMTEL network for subId 11.
   - No direct IWLAN reset is currently recommended.
   - Risk: Level 0 if only observed; Level 3 to Level 4 if forced directly.

Current closest theoretical chain:
  subId 11 -> no subscription
  -> CarrierConfig CLEAR_CONFIG/no-SIM config for phoneId 1
  -> ImsResolver slot 1 MMTEL/RCS remove under subId=-1
  -> restore subId 11
  -> CarrierConfig ESSENTIAL_LOADED/LOADED
